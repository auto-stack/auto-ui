# G11/2d：从 Node 最小验证到完整示例

2026-10-31，设计 v1；仅规划。依据[共同作者模型](declarative-authoring-model.md)、[目标草图](g11-2d-target-source-sketch.md)、[016 已交付 Spec](../../specs/auto-graphics/node2d-pilot.md)及原 G11 消费合同。

## 目标与分仓

用普通 Auto 模块、`node/model/view-2d/on`、`Life.Start/Tick`、匿名 `msg` 与具名引用，表达原 G11/2d 的完整玩法。作者维护声明源码；场景 JSON、对象 ID、槽和生成单元由工具生成。生成后仍可复用既有运行服务，不要求一个模块对应一个 VM。

- [auto-ui/017](../../plans/017-autographics-g11-2d-node-authoring.md)：补齐有限 Node2D 作者入口、声明驱动的资源/几何/绑定生成、完整左右输入、事件路由、原额调度及新 Run 接线；提供可搬迁生成器和固定运行器的消费契约。
- [ag-examples/007](../../../../ag-examples/docs/plans/007-autographics-gallery-g11-2d-node-migration.md)：硬等 017 实际交付，改写 G11/2d 内容，承接原 51 项二维 oracle、目录、参数变体、公开启动与单项离线包。

017 不写 Gallery，007 不在内容仓实现转译器或玩法服务。G11/3d 的源码、旧锁与 25 项历史验收保持；仅二维升级，因此 Gallery 必须按子入口选择锁与验收，不能把整个 G11 静默升引擎。

## 016 提供的基础与仍需补齐的面

016 交付 `932bd5f`（独立终审实现 `9eb1d0e`），已证明模块、同定义实例隔离、事件和真实销毁可以经过 Auto 与 GPU。它是显式研究切片：`scene::template_id/build_scene_json` 仍固定 Player/Coin/Hazard 与部分坐标；`input.axis(Left, Right)` 实际仅映射 Right；编排只读取一条事件，存在固定参数名和首个业务 handler 的接线。不能据此宣称完整草图可执行。

017 从结构化领域模型推导静态角色/地面、有限运行实例、模板、触发和相机。组件/模块/字段的业务名字不得决定图形类别、角色、事件语义或模板 ID。最低区分控制是改名、重排声明、修改资源/位置与加入同类型实例，实际结果仍按声明变化；不扩为任意规模通用引擎。

## 本阶段的语义取舍

1. 保留原玩法：左右走、三件不同形状/颜色/大小的物品、巡逻危险、集齐才赢、左侧越界失败、终局停止角色移动、新鲜 Enter 重开。无跳跃、声音、HUD 或新平台。
2. 保留原 32 credits、8 个运行槽、8 对触发及 N 产生/N+1 消费的时序。移动读取最多一条事件，静止最多三条；未读事件仍按旧 profile 丢弃，不承诺跨 tick 队列或同 tick 八事件全处理。
3. 原脚本在存在事件的 tick 不写危险位置，但其 Auto 巡逻状态仍推进。这是本次兼容要求；未来消除该调度约束须单独证明与规划。不能把“每 Node Tick”实现为每次都无条件调用昂贵图形服务。
4. `on_enter` 必须按实际 phase 与绑定目标路由，不能把任意首个 handler 当进入事件；stay/exit 不可伪作 enter。具体服务拼写、payload 与可选参数由 017 的有界整链任务冻结，沿既定 Node/Life/msg/use 语义，不发明另一套脚本语言。
5. 重开映射既有 accepted round request：新 Run 重建本局状态、角色、相机、实例和订阅；不是本阶段新增任意 key 子树重建。目标草图中的 App/key、集合 API 和局部重建仍是后继提案。本阶段可用普通有限标量/枚举或既有容器表达三件物品，不要求实现通用集合库。
6. 生成产物是只读构建结果。正常启动消费已验证产物与固定运行器；编辑任一被使用模块后必须经同版本生成器重新准备，旧 hash/旧报告不保持 Ready。源码和全部小型产物随单项包，可离线重建；运行包不依赖编译器在线安装。

## 预算先证与止损

有界任务先跑完整 main/alt，而不是再做只有一个 Coin 的探针。候选移动收集账为左右读取 2 + sweep 26 + next/pair/phase 各 1 + despawn 1 = 32；原事件 tick 跳过危险图形写，静止三收集另计。这只是候选账，须校准真实初始化、普通、收集、终点、失败、重开、静止三收集及 VM 成本。不能借 Rust 缓存绕过计费、读私有 VM 全局或提高限额。若无法保持原验收与原额，记录反例后回规划，不宣称交付。

本阶段不实现 3D Node、多呈现选择、混合 UI、Life.Frame、ACE/AOT、ECS、通用编辑器往返、完整 M2 游戏，也不把诊断/来源追踪提升为限制模块化的产品目标。
