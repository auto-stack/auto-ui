# AGE M3：2D／2DHD游戏能力与复杂3D图形扩展

2026-11-04，路线决议v1。用户调整：考虑ACE集成所需时间，AGE与现有AutoUI正式融合顺延M4；M3优先增强2D/3D，支持更复杂的游戏/图形应用，以俯视角2D/2DHD国风种田游戏和three.js示例覆盖为两条主要验证线。本轮确定方向，不取Plan号、不建树、不实施或改当前M2验收。

## 1. 里程碑划分

| 阶段 | 主要目标 | 交付边界 |
|---|---|---|
| M2 | 两完整小游戏、Gallery与新语法基础UI＋2D＋3D同应用组合 | 原M2-01..10/两游戏/12项22入口47变体及具名必需门不改 |
| M3 | 从有限平台游戏走向更复杂2D/2DHD与3D应用；承载游戏＋能力示例共同驱动公共引擎增强 | 冻结具体游戏切片、画面、能力样本和容量/性能门后分批立约，不以效果截图认领完整能力 |
| M4 | AGE与现有AutoUI正式融合，Schema方言/共同编译运行链接通 | 等ACE所需Schema能力成熟且旧编译器替换实际启动；001起UI Demo兼容路径归本阶段 |

M3不等待ACE正式融合才能推进；涉及ACE专属能力的切片仍须真实依赖交付，不能假定AOT/新VM已经可用。M4方向与进入门见[融合路线](m4-autoui-integration-roadmap.md)。M3不提前扩旧手写UI parser成完整生产UI，也不撤销现有M2的有限UI验证。

## 2. 二维主线：俯视角与国风种田承载游戏

早期[图形/Forge战略](../../../../auto-lang/docs/design/strategy/autographics-forge-v06.md)保留国风种田、资源/战斗、装备/符箓方向；当前只恢复为M3承载游戏方向，不宣称已有完整规则/资源或正式产品合同。先做可玩切片，再扩内容，不把整款商业游戏的全部系统暗中装进一份能力计划。

| 能力域 | 优先调查/增强候选 | 可观察验证方向（待具体合同冻结） |
|---|---|---|
| 地图与视图 | 俯视地图/图块与图层、角色/物件遮挡排序、跟随相机和区域切换 | 角色穿过遮挡前后排序正确、地图切换/重开保身份、实际场景可操作 |
| 移动与交互 | 四/八向运动、碰撞/区域查询、交互目标与可创建销毁物件 | 边界/阻挡/目标选择正确，不以每游戏专用Rust规则实现 |
| 表现与资源 | 精灵/方向帧动画、资源复用/图集、必要光影/粒子/声音与基础游戏界面 | 运动/交互/视觉音频同状态，资产来源/许可与离线闭包完整 |
| 玩法承载 | 小地图内移动、交互和种植→生长/时间→收获的可玩闭环；背包/存取档等按切片需要冻结 | 真实Auto model/on组织业务，状态/物件和保存恢复真实，不只预录轨迹 |
| 规模与工具 | 更多活跃/休眠对象、地图资源组织/编辑、加载/卸载、必要存档与诊断 | 明确地图/对象/更新规模及合法边界、坏件与恢复、资源owner和实际帧时/内存 |

这些是能力候选/拆分依据，不是已实现或全量首批必交付清单。2DHD的具体画面构成（纯2D高表现或2D精灵结合3D空间/光照等）需用目标源码/画面草图冻结；不因名称就认定45度等距、固定摄像机或某种渲染管线。原M2未含种植/背包/对话等，不回填为旧计划遗漏。

游戏逻辑继续由真实Auto执行；公共引擎可提供通用地图/碰撞/动画/资源服务，不编写专用种田业务替代作者代码。Node/use/具名资源、局部状态/事件和声明/运行组织分离继续沿既有方向；单文件/单模块或全世界事务不是前提。

## 3. 三维主线：以three.js示例建立可追踪覆盖

目标是持续覆盖three.js各类示例所体现的图形能力，逐项可查；以官方示例目录为对照，不用少量相似截图声称全覆盖。2026-11-04查阅[官方示例页](https://threejs.org/examples/)及[官方目录files.json](https://github.com/mrdoob/three.js/blob/dev/examples/files.json)，包含WebGL/WebGPU、材质/模型动画/光照、后处理、性能/平台相关等不同类别。这里是方向调查，**未冻结M3参考tag/commit或全量条目数**；dev分支只作本次观察来源，正式覆盖表必须固定不可变版本/目录摘要，并记录后续上游差异。

拟按公共机制逐批扩展：

- 材质/纹理/光照与阴影、环境/反射等表现基础。
- 模型与动画、几何与交互、动态实例等场景表达。
- 粒子/后处理与多pass、实例化/LOD/剔除和较大场景的资源/性能。

首次盘点对固定目录**每一条**登记：上游示例ID/版本/素材许可→所需能力→AGE公共接口/对应正常Auto示例→实际运行/画面/交互/资源和性能oracle→已覆盖/部分覆盖/缺口/平台依赖及owner。重复机制可共享底层实现，但各必需变体保持可查；不得跳过复杂条目后将剩余百分比称“全部”。具体M3必交付批次/分母与后续扩展在正式合同冻结，超范围条目须显式保留，不擅自删分母或凭“参考矩阵”宣告已完成全目录。

AGE底层仍wgpu；复现图形/交互能力不自动承诺three.js JavaScript/WebGL API兼容。WebGPU/浏览器DOM、CSS呈现、WebXR/设备/worker等有平台条件的条目分别记录，不能用原生窗口绿代浏览器/XR绿，也不因M3名称自动把全部跨端产品化加入已有合同。需要新平台支持时按实际缺口另立约，当前只定覆盖方向。M2原Gallery12项22入口与既有固定参考版本保历史，不悄悄替换为新目录。

## 4. 引擎与内容分仓、预算与实施路径

引擎/自身Specs/能力计划归auto-ui；图形小示例、综合示例和完整游戏归当前ag-examples，未来实际完成020更名后才按age-examples新根继续。同一内容仓内examples/、showcases/、games/分别承载教学、综合验证、游戏，不重新初始化仓库或重启编号；国风游戏具体项目名/位置待首份合同确认，不预建目录/素材。

可按“引擎公共能力、游戏可玩切片、对应Gallery示例”分批并行准备；内容完整接线只消费上游实际交付、固定来源，不追tip。2D和3D路线共享资源/模型/动画/渲染等写面需owner短窗，GPU/音频/焦点与重型门单实例；不接管其它在途树。

现有M2实验profile与原预算/SDK锁不改。更大地图/对象与复杂3D必然需要先验证容量：每个M3切片应先固定代表性规模/合法最坏轨迹、CPU Tick/加载/生成/绘制分别计量、实际对象/资产owner与内存/帧时、边界反例及恢复；新资源域/费用或上限变化另有显式profile/兼容合同，不把8状态Node/128行/32credits永远当生产语言规则，也不静默抬额、停掉模块或用Rust业务凑绿。旧VM/编译成本是否满足目标必须先证；依赖不足时具名调度/重规划，不假定ACE已替换来掩盖瓶颈。

M3首轮规划前先做当前能力×国风可玩切片×固定three.js目录差距盘点，产出可排序的能力包。先证复用/瓶颈与完整最小链，再取本仓新号立独立引擎/内容合同，按work/独立review/merge交付。不会本轮预取一串计划号、承诺工期或制作新源码/探针。

## 5. 阶段完成与当前范围

M3完成需后续明确冻结的2D/2DHD可玩切片、复杂3D能力批次、正常Auto作者与公开运行/资源发行、实际交互/画面与容量性能正反例、独立复审/来源与兼容证据齐；完整商业国风游戏与three.js全目录的最终覆盖不能从本方向文档自动推断完成。覆盖/缺口表持续保留，尚未冻结的条目不是获准删除，必需分母未证不充pass。

旧M3 AutoUI融合路线由本次决议顺延M4，Schema/ACE进入门与001起UI Demo兼容路径全部保留。M2当前计划/验收、019历史交付、020既定M2后维护窗口与计划身份不变；020不因M4等待自动再推迟到M4，也不成为M3/M4引擎能力的前置。本轮只更新设计与路线，无新Plan/counter/工作树/材料scope/构建/GPU/素材/实施/迁移/发布。
