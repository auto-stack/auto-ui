# AGE M3：与现有AutoUI正式融合

2026-11-04，路线决议v2。用户确认：M2之后，M3主要目标是AGE与现有AutoUI合并。用户进一步确认：Schema方言与ACE替换旧编译器应统一考虑，M3正式接入等待相应前置。本页确定下一阶段方向与边界，不是执行合同；本轮不取Plan号、不建树、不实现或切换默认入口。

## 1. 阶段定位

| 阶段 | 主目标 | 与下一阶段的边界 |
|---|---|---|
| M2 | 新Auto Node/use/model/msg/on下，完成两款游戏、Gallery及基础UI＋2D＋3D同应用组合（M2-01..10） | 048/049的有限基础UI与显式研究入口证明组合链；不据此称现有AutoUI生产体系已融合 |
| M3 | 等ACE的Schema方言体系成熟且旧编译器替换实际启动后，统一设计AGE与AutoUI正式融合 | 采用共同Schema方言/编译链，接通现有UI体系与2D/3D；生产消费/兼容与具体组件后端覆盖另立合同验收 |

AGE源码已在auto-ui，纯源码归仓879与未来内容目录更名020分别保原身份。M3的交付重点是语言、编译、运行和组件体系接通；目录更名不会替代这些功能验收，也不是融合的必要前置。内容示例继续归内容仓，M3不自动把示例搬入引擎仓。

## 2. 主要工作面

1. **Schema方言与共同作者模型**：UI/2D/3D沿ACE的Schema语言包/方言体系定义并接入共同编译链；不将现有手写UI parser继续扩充作为M3正式目标。对齐Node的model/msg/on/use与view/view-2d/view-3d，普通AutoUI组件可与图形节点组合；生产widget与新Node的语义/表示需明确映射，兼容迁移后再决定旧名字退役，不凭改关键字宣称融合。
2. **复用现有UI体系**：接通已存在的组件、布局、属性绑定、事件、样式/主题与资源。按真实公共能力选代表性组件做端到端集成，避免在AGE维护第二套彼此漂移的UI业务/控件实现；全量组件覆盖单列矩阵，不能用M2四类基础元素代替生产能力。
3. **统一状态与生命周期**：保留AutoUI已交付的组件实例隔离、props/emit与Store的App归属、迟到回调隔离、主题scope；协调图形实例、共享挂载、Life.Tick、UI事件/重绘、应用/窗口寿命。一个状态owner不因多出口重复推进，不以同字段名自动共享状态，也不强迫声明树等于运行存储。
4. **生产宿主与渲染接线**：将AGE嵌入现有AutoUI编译/运行/窗口、布局、输入、焦点/捕获、资源/device/合成路径；保已有UI行为与实际图形输出。以生产公开入口运行和现有应用回归证明，不止研究入口或Rust定制demo。
5. **编译与开发链收口**：在ACE实际替换旧编译器的路线中，统一对齐UI/2D/3D Schema、领域表示/IR投影、诊断、产物身份、模块/资源闭包和构建配置。给出旧UI工程的迁移/并存/默认切换/回退路径，核实际交付接口和兼容证据，不把两个不兼容语言依赖图强塞同一Cargo图。

以上为工作方向，不冻结具体API、工期、预算或实施Plan数量。旧实验profile价格/32credits等不是永久生产语言规则；M2交付保持其原合同，M3若调整资源/数值/执行支持必须显式设计和版本化验收，不能静默抬预算或删旧样本。

## 3. 实施次序与进入门

M2按既有048→049→AG021及原必需门收口，不把M3新增生产融合要求倒灌在途Plan。UI043/044、UI状态/主题/Reload等路线分别保持自己的owner和合同，不以标题当成整项串行前置。

### 3.1 正式接入前置

2026-11-04用户明确：现有AutoUI仍以旧的手写语法实现为主，AGE建议与ACE一样采用Schema驱动的方言体系，因此应等ACE完善并开始替换现有Auto编译器时，再统一考虑AGE/AutoUI合入。下列条件共同成立后，才进入M3正式接入设计与实施立约：

- M2按原合同收口；不以M3等待为由删改M2-01..10，也不将生产UI全量迁移追加给048/049/AG021。
- ACE的Schema语言包/方言与相关编译接口已有可消费的实际交付证据。具体支持域、Schema/语法规则、CST/AST与IR投影、诊断/源码位置、模块/增量与失效边界由ACE owner提供；不把设计草案或局部实验当完整平台已成熟。
- 替换现有Auto编译器的工作已经实际启动，明确所用入口/版本、迁移owner、兼容/并存/回退路线；AGE与AutoUI随这条共同编译链统一接入，不提前在旧链上做一次完整生产融合再全量重做。

“ACE完善”指正式接入所需能力达到可消费成熟度，具体门在当时实施合同冻结，不泛化成所有未来ACE特性都必须完成；“已开始替换”也不等于旧编译器已全部退役。此次明确了等待时序，不宣称上述条件已经具备，不自动更换SDK或切默认。

### 3.2 等待期间与启动后的路径

等待期间可以整理现有Demo/组件/Blueprint能力覆盖、旧行为与资源/输入/状态合同、源码样本及Schema需求；不预先为M3扩充完整手写UI parser、不启动全量Demo引擎迁移。M2已有有限研究入口继续服务其既定验证，不能把它们当长期Schema实现或生产UI已统一。

前置具备后，先做**Schema方言接入＋现有UI语义映射的有界端到端先证**，再按真实缺口分批立中等规模Plan。统一入口形成后，从`examples/ui/001-helloworld`开始，按能力依赖由浅入深推进全部UI Demo兼容：文字/布局/主题→状态/事件→表单/列表/滚动→菜单/actions/Blueprint→媒体/阅读/编辑等。编号作导航，批次按真实依赖冻结；原Demo业务、样式/主题、交互及验收保持，001当前的文字选择/复制、主题/模式绑定等也须承接，不能仅画出一行字就关闭整例。

Demo通过指在AGE公共路径**正常运行**，覆盖原有显示、绑定、交互、资源与生命周期；逐项形成Demo→组件/属性/事件→状态/资源→后端覆盖表。全部Demo绿形成强兼容证据，但未被Demo覆盖的组件变体/错误态仍须具名补验；Feature/FeaturePack领域能力不因Demo显示成功自动交付。此处只定推进方式，不新增计划号，不提前冻结全部组件/后端矩阵。

后续再完成生产宿主/资源/输入接线、真实UI＋图形应用、必要迁移与默认切换。源码合入、默认入口切换和旧路径退役分别验收，失败可回退。相应独立review与源/版本/SDK身份按真实合同核验。

## 4. 完成判据的方向

代表性现有AutoUI应用从生产公开入口使用普通组件/主题/状态与AGE 2D/3D，在同应用中保持绑定、事件、焦点、实例/Store隔离和正确画面/资源寿命；业务由Auto执行，已有UI消费者有明确兼容证据。新旧工程/源闭包、诊断、资源发行、必要修改重建与坏件恢复可复验；独立review和冻结交付齐全。具体必需组件集/原生输入与后端矩阵在M3实施合同明确，不能用“源码同仓”或M2少量基础UI绿灯认领M3。

首批融合以当前桌面能力为落点；Vue/DOM与WebGPU、移动原生/Web分别按既有平台边界研究/立约。“同一个程序跑在任何屏幕”仍是长期方向；DOM overlay、可采样UI和深度正确的三维UI分别验收，不自动混称。M3等待ACE所需Schema能力与编译器替换实际启动，并统一接线；ACE所有后端/AOT全面替换、完整HMR、CPC、ECS、全平台产品化的全量交付不随M3命名自动捆绑。相关接缝按真实依赖纳入具体合同。
