# AutoUI 示例归属与搬迁约定

> 状态：设计决定 v0.1，2026-10-29；归属选择与搬迁纳入 [auto-ui/PLAN-007](../../plans/007-autoui-tree-theme-and-examples.md) r3。当前只改设计和计划，示例源码尚未搬迁。
> 源：auto-lang/examples/ui；目标：auto-ui/examples/ui。官方主题实现与数据包归 auto-ui，不复制到每个 app。AutoOS 产品 app 不迁入本目录。

## 1. 选择框架仓内示例

| 方案 | 优点 | 当前代价/判断 |
|---|---|---|
| 留 auto-lang/examples/ui | 既有路径暂不变 | UI 框架、主题、示例与测试 owner 分离；UI 测试继续反向依赖语言仓的应用资产，不适合作为长期来源 |
| auto-ui/examples/ui | 主题/组件与教学例同仓修改、复审、验证；现有 UI 包直接消费本仓资产 | 需要一次显式跨仓搬迁和实际引用修复；推荐当前采用 |
| 新 ui-examples 仓 | 内容可独立发行，适合以后固定框架版本的示例集合 | 新主题仍在试用，增加版本/清单/CI/发布协调；目前没有需要独立发行示例的明确消费者，不立即建仓 |

ag-examples 是固定外部引擎的 Gallery 内容消费者，已经具有独立目录/打包/资源契约。UI 教学示例目前同时是框架兼容与交互测试的真实输入，并非必须采用相同拆仓边界。后续如果需要独立示例发布、独立贡献/CI、版本并行支持或安装包集合，可按实际需求再拆 ui-examples；此次不建立第二个权威示例源，也不预建远端仓。

## 3. 分两阶段，单个计划交付

阶段A：搬迁全部适用受管资产、测试与共享stylekit，逐文件记录原路径/目标路径/字节长度/SHA-256及合法变更；先保持业务和主题语义。阶段B：在目标路径实施新主题与首批002/005改写。阶段A的来源校验不能拿阶段B修改后的主题源码倒推为“原字节一致”。

保留目录身份、pac项目名/应用ID、assets、tests及其许可证/来源；不按重复031编号合并，不随迁移删验证例。忽略的node_modules/target/缓存与本地配置不盲搬、不入库。执行时发现合法未跟踪来源先辨认并记录，不覆盖用户文件。

跨Git仓不能用一个git mv保留完整跨仓历史。保留来源提交、文件清单和哈希，目标提交与源仓删除提交形成可读回的迁移收据；不重写两仓历史。真实搬迁/删除只能在该Plan实施组中完成，按仓验证resolved绝对目标后操作；禁止junction/symlink。

## 4. 依赖与旧入口处理

- UI registry、生成/运行工具、测试与媒体夹具以新目标为真实来源；Man CLI/desktop入口、网站/脚本的现行引用按owner修复，不以主检出旧树为隐藏fallback。
- 语言侧消费者采用固定的UI示例来源或有明确来源/哈希的有限语言回归fixture。后者是测试输入而不是另一份可编辑demo。不能把整棵examples复制到语言测试目录规避迁移。
- 旧 auto-lang/examples/ui 可留一份README定位指引，不留可运行.at镜像，不保留目录搜索顺序猜测，不建链接。全部读取必须在旧源码不存在的条件下验证一次。
- 现行文档/README/CLI帮助与注册入口更新；历史archive中的源码路径保留历史意义，由迁移映射解释，不全仓篡改历史日志。
- ACE固定语料/887治理清单由其owner接受新来源身份和映射。路径变化不删除AP-16、不重写行为oracle、不降低支持要求；如有固化快照，以原字节与来源身份明确区分活体示例。
- 共享依赖如blueprints通过固定来源/显式依赖定位，跨仓组可以有相邻checkout；fresh/locked及至少一个不同绝对根重定位必须能读取新来源，不靠D:/autostack主检出兜底。

## 5. 验收与不扩面

闭合条件包括37目录分类/381受跟踪文件基线对账、动态差异清单、旧源不再作为运行资产、stylekit与041/015实际依赖解析、UI/Man/语言已确认现行读者回接、代表性双端运行与media fixture读取。实际全量义务按启动后的消费者清单冻结，不能用代表性运行替代清单内必需检查。

本计划不迁 AutoOS 产品 app、不把其业务回灌教学例，不搬 examples 下其他非UI项目，不接管ACE/887实现或要求所有历史归档改写。超出原公开端口的通用语言语义变更按主题计划T-01重规划。
